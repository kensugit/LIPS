# Search catalog snapshot identity

`CatalogSearchSnapshotProvider.CaptureAsync(ct)` returns `SearchCatalogSnapshot(Version, Options, Suppliers)`. The version is `search-catalog/v1:` plus lowercase SHA256, derived from actual data in SupplierProducts, Suppliers, SourceEvidence and ProductSearchDocuments. These four fixed tables are read as PostgreSQL `row_to_json(t)::text`, ordered by Id. UTF-8 records use typed frames with an eight-byte big-endian byte length; explicit table-start/end frames preserve empty-table and record boundaries. Every row of historical SourceEvidence participates conservatively. No SourceDocuments.Content is read, and no row material, credentials or connection string is logged or returned.

The provider creates an owned REPEATABLE READ transaction and marks it READ ONLY, unless the caller already owns a REPEATABLE READ or SERIALIZABLE transaction. In the latter case it uses the existing transaction without committing, disposing or changing its isolation. A weaker caller isolation is rejected. The digest and options are obtained in the same snapshot. Parent Web orchestration must perform the second identity check and final query within the same caller-owned transaction; the provider alone does not establish that workflow.

Option arrays are distinct and ordinal-sorted, with blank text values omitted. Vintage values use the existing VintageNotation normalization. Supplier filter values are unique codes; a separate Code/Name list provides display labels. Limits match the existing bridge contract (250 countries, 1000 regions, 100 types, 100 volumes, 500 vintages, 1000 suppliers; text200 UTF-16 units, volume1..100000). Exceeding a limit fails rather than truncating silently.

Identity covers PostgreSQL's actual JSON text representation, not a cross-engine canonical JSON scheme. A representation/schema change can conservatively invalidate it. This is not a commit hash, row count, permanent business identifier, or authentication token. The full scan cost and cancellation behavior need runtime measurement on an isolated production-like copy before deployment.

Verification is pure hashing/framing/order/mutation and options-contract tests. No real database integration or production execution is claimed. Existing Pkcs/Xml10.0.12 NuGet audit warnings block the unchanged warning-as-error build; local test execution may demote only NU1902/NU1903 while still displaying them. Dependency remediation is not included in this file change.

## 操作手順

1. この候補を起動したローカル確認環境で `/workspace.html` を開く。
2. 「PCの取引先別フォルダーを一括取込」で、取引先フォルダーそのもの、または複数の取引先フォルダーを含む親を選ぶ。例：`取引先別/LUC/在庫2026-08-17.xlsx`。
3. ファイル一覧を確認する。資料日付がファイル名にない資料は、行の資料日付へ入力する。選択だけでは送信しない。
4. 「一括取込を開始」を押す。結果は1ファイルごとに更新される。
5. 「結果を保存」で相対パス・状態・理由・商品数・取引先・資料日付・登録済み原本IDと停止フラグをJSONとして保存する。原本IDはAPI/結果JSONで提供し、結果表には表示しない。画面内の結果は再読込で消える。成功のDB取込履歴は残る。
6. 止める場合は「このファイルの後で停止」。現在送信中の結果を待ち、未処理の資料を残す。再開は「一括取込を開始」で未処理分のみ。
7. 通信中断とDB保存結果不明は保留し、キューを停止する。HTTP 200でもStopQueue=trueの応答で後続送信を止める。通常の入力不備による保留は続行する。未処理ファイルは残し、不明ファイルは自動再送しない。履歴確認後に明示的に再選択・再取込できる。同じ取引先・同じバイト列は別名でも重複登録しない。

## 対応と状態

対応フォルダー名：`LUC`、`WINE_TO_STYLE` / `Wine to Style` / `ワイントゥスタイル`、`KINOSHITA` / `木下インターナショナル`、`TOA` / `東亜商事`、`AMZ` / `エイ・エム・ズィー`。全半角・大小文字・空白を正規化し、完全一致で判定する。複数の異なる取引先がパスにある場合は保留。

|状態|扱い|
|---|---|
|成功|登録完了。または同じ取引先・同じ原本ハッシュが登録済み（商品数と原本IDを返す）|
|保留|取引先不明/不一致、日付不明/不正/不一致、Excel判定の曖昧さ、列・値・SKUの問題、同日別内容/旧版、保存結果不明|
|未対応|PDF・旧Excel・画像など、または指定レイアウトに合わないExcel|
|失敗|空/過大ファイル、不正な相対パス、予期しない処理エラー。履歴と資料の確認が必要|

対応フォルダーの指定Excelと標準CSVを使用する。CSVはフォルダーを取引先指定として扱い、独自CSVの自動列推測は行わない。PDFなど別CLIの既存インポーターは今回のWeb経路へ接続していない。オルヴォーの複数資料の組合せ取込も対象外。

資料日付は `YYYY-MM-DD`、`YYYY.MM.DD`、`YYYYMMDD`、年月日表記から解釈する。月日の1桁も対応。入力日付とファイル名が矛盾する場合は保留。更新日時・送信日から推測しない。月までの資料には明示的な資料日付入力が必要。

フォルダー取込では、同一取引先の既存資料日付以降に対して、新規資料が同日別内容または古い版の場合は自動上書きせず保留する。同じハッシュの判定は日付衝突判定より先。PostgreSQLの既存transaction/advisory lock内で判定し、並行送信でも同じ原本を重複作成しない。通常の単票取込の順序規則は変更しない。

原本バイト列、元セル、行、価格・在庫原表記を保存。LUCの◎、木下のCS、AMZの↑↓を正確な本数へ置換しない。東亜の★は入荷待ち。税込明記なしは税抜。不明在庫を欠品へ変換しない。

## 制限と実装

- ブラウザーで最大1,000ファイル・合計500MB。1ファイル20MB。選択フォルダー内の未対応ファイルも結果に残す。
- `POST /api/import/folder`: multipart `file`（1件）、`relativePath`（1件）、任意 `observedAt`。既存操作ヘッダー・Origin検査を通す。
- サーバーの取込は1ファイル1transaction。途中の保留・失敗が他の正常ファイルを取り消さない。クライアントが順次処理するため、バッチ完了を待たず結果を表示でき、gatewayの上限変更は不要。
- 相対パスをサーバーのファイルパスとして使用しない。ルート指定、ドライブ、`..`、制御文字、過剰な長さ・階層を拒否。
- XLSXの展開後サイズ100MB、ZIPエントリー2,000件を上限とし、外部リンクを拒否。
- Chrome/Edgeのフォルダー選択を対象として確認。空フォルダーやブラウザーが提供しないファイルは列挙できない。OneDrive未取得ファイルのダウンロード・全体完全性や他ブラウザーは未確認。

# 商品カタログ：取込・横断検索・商品確認

2026-09-17。独立したローカルPoCです。本番環境・iWSET運用DB・酒道楽DBへの変更はありません。

## 起動と検索

1. outputsの **Start-Catalog-Demo.cmd** をダブルクリックします。
2. ブラウザで http://127.0.0.1:55440 が開きます。初回はWine to Styleの1,061商品が登録済みです。
3. 容量750ml・ヴィンテージ2023・税抜価格5,000～10,000円、その他は未指定で検索すると63件です（サンプル追加前）。
4. 上部の **取込・横断検索・商品確認** を押します。

## CSVと酒道楽サンプルを取り込む

1. **標準CSVサンプルをダウンロード** から2商品のCSVを保存します。outputsの `demo-2026-09-17.csv` も同じ内容です。
2. 保存したCSVを選び、資料日付2026-09-17、仕入先コードDEMO_SUPPLIER、仕入先名は初期値のまま **内容を取り込む** を押します。「2件：取込が完了しました」と表示されます。
3. 同じCSVを再度取り込むと「取込済みのため重複登録しませんでした」と表示されます。
4. **匿名サンプルを取り込む** を押します。初回4件、再実行は更新0件です。実在しない確認用商品であり、実際の酒道楽DBには接続しません。
5. **横断検索・商品確認** を押します。初期検索語「確認用サンプル」で5件（仕入先2＋酒道楽現役3）。**終売商品を含む** を選んで検索すると6件です。

サンプル投入後、通常の商品検索の仕入先商品総数は1,063件になります。検証中に使った架空データは別DBに隔離してあり、利用者用DBにはまだ追加していません。

## 同一商品候補を確認する

1. `DEMO-INTERNAL-001` の **候補を確認** を押します。
2. 名称・容量750ml・ヴィンテージ2023が一致する `DEMO-SKU-001` が候補になります。2022年の商品は候補になりません。
3. 内容を確認して候補を選び、**選んだ候補に紐付ける** を押して確認ダイアログで承認します。
4. 状態が「紐付け済み」になります。表示方法を **共通商品でまとめる** にして検索すると、同じ共通商品の下に2レコードが表示されます。
5. **候補を確認 → 紐付けを解除する** で対象レコードの紐付けを解除できます。他レコード・共通商品・原本は残ります。
6. **今回は紐付けない** は「保留」として記録します。後で再確認できます。
7. 酒道楽行の **元データ** で元コード・カナ・状態・保存済み履歴数を確認します。未紐付け商品も検索結果に残ります。

候補は名称の正規化・容量・ヴィンテージ一致に限定しています。同一商品であることを自動確定しません。仕入先の価格と在庫は各仕入先行に残り、酒道楽行へ転記しません。

## Excelとフォルダー自動取込

- Wine to Styleの元Excelも取込画面から選べます。資料日付はその表の基準日を指定してください。Excelでは仕入先をWine to Styleに固定します。
- 標準CSVはUTF-8／CP932対応。必須列は `SKU,ProductNameJa,VolumeMl,Price,Inventory`、任意列には `Vintage,Tax,Type,Country,Region,JAN` などがあります。サンプルをテンプレートにしてください。
- Priceは希望小売価格、Taxは空欄／税抜／税込。空欄は税抜。金額なしやオープン価格は数値にしません。Inventory空欄は不明です。
- 自動取込は画面の **フォルダーから自動取込** に表示された専用フォルダーを使います。その下に `DEMO_SUPPLIER` を作り、`demo-2026-09-17.csv` を保存します。Excelは `WINE_TO_STYLE` フォルダーへ置きます。
- ファイル名には資料日付 `YYYY-MM-DD` が必要です。起動中に通常10～15秒程度で検出します。20MB以下・空でないcsv/xlsxが対象です。原本は移動・削除しません。
- **取込・操作履歴** で結果を確認します。失敗は最大3回まで自動再試行します。形式・列・日付等を修正してから **失敗した資料を再試行** を押してください。内容を変更したファイルは別の内容として検出され、以前の失敗記録も残ります。
- 同じ仕入先・同じファイル内容は重複取込しません。別日に同一内容を再提出しても新しい在庫確認時刻としては扱わない、今回のPoCの仕様です。

## 終了

ブラウザを閉じ、outputsの **Stop-Catalog-Demo.cmd** をダブルクリックします。Webと専用PostgreSQLが停止し、登録したデータは残ります。

## 確認結果と残項目

ビルド成功（警告0・エラー0）、自動テスト28件成功・スキップ0。ブラウザは既存16＋検索条件18＋追加操作28の合計62項目成功。PC幅とスマートフォン幅の画面を確認しました。新しいDB更新SQLの空DB適用・再適用、モデル差分なしも確認しました。

追加機能はローカルで操作確認可能です。次は実運用向けの以下の工程です。

- 酒道楽の実接続：取得方法・テーブル定義・読取専用資格情報・現役/終売の方針確定後。現在はfixture全量同期・レコードハッシュ・履歴保存まで。実運用の差分watermarkは未実装。
- 自然文の意味検索：日本語FTSの評価方針、Embedding提供元・資格情報・外部送信範囲の確定後。現状はSQLの構造化検索と部分一致検索。
- 共有利用：認証・権限、複数利用者の監査、候補精度評価、運用ジョブ化。現状はこのPCだけの確認モードで、共通操作者として履歴保存。
- 汎用Excel/PDF/画像抽出は後続。現在のExcelはWine to Style専用。

今回追加した管理画面の横断検索は商品名/コード・取得元・終売条件です。容量・ヴィンテージ・価格帯の詳細条件は従来の商品検索画面にあります。
本番デプロイ・masterマージ・pushは行っていません。

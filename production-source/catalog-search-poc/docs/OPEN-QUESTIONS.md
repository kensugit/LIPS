# 実装に足りない情報

## P0: 最初の実データ取込前に必要

1. **代表ファイル**: 仕入先カタログ/在庫表を2〜3種類（機密なら匿名化可）。列名、複数Sheet、結合セル、数式、文字コードを確認する。
2. **酒道楽の取得方法**: PostgreSQLへのread-only接続、CSV export、既存Python同期のどれをPoCで使うか。
3. **酒道楽Schema**: 商品PK、商品名/カナ、JAN、容量、仕入先コード、分類、終売/有効フラグ、更新日時、備考の実列名と型。
4. **検索対象範囲**: 酒道楽の全商品か、現役商品だけか。過去/終売品を既定検索から除外するか。
5. **価格の意味**: この表の希望小売は`REFERENCE_RETAIL`、税込表記なしは税抜と確定済み。別資料から仕入価格、単品/ケース、通貨、送料をどう識別するかは要確認。

## P1: Matching評価前に必要

6. Canonical Productの粒度: 正規/並行、箱有無、ラベル違い、ロット/デゴルジュマンをどこまで別商品とするか。
7. 酒道楽側の仕入先別商品が同一物である正解データを最低50〜100組。
8. JAN欠損時に信頼できる識別子と、仕入先コードの再利用有無。
9. Vintage不明/NV、容量表記、セット商品の扱い。
10. 自動Linkを初期PoCで許すか。推奨は候補表示のみで、人間確定。

## P2: 運用設計前に必要

11. 誰がReviewし、修正ルールを全仕入先へ適用できるか。
12. 文書投入頻度、最大ファイル数・容量、履歴保持年数。
13. OpenAI APIへ送信可能な情報範囲と保持ポリシー。
14. PoCの実行場所（P14s、専用Windows機、Ubuntuサーバ）と同時利用者数。
15. 認証方式（PoCは社内限定・単一管理者でも可）。

## 推奨の暫定値

- 酒道楽同期: 既存Python同期と分離したread-only exportから開始
- 検索既定: 現役商品を優先、過去商品はトグルで含める
- 自動Link: 無効。0.995以上もReviewで検証後に有効化
- Embedding対象: 商品名、別名、生産者、産地、説明、酒道楽商品名/カナ/備考。価格・在庫は除外
- PoC利用者: Admin 1〜3名

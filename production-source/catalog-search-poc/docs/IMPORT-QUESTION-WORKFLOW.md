# 取込疑義の確認・回答・再開

本人依頼: Slack1791766575.053619、続行1791766584.429509。以下は最小実装範囲と順序。現時点では実装未完。

## 現状との接続

FolderImportEndpointsの1ファイルPOST、FolderImportServiceのHeld、folder-import.jsのファイル一覧を利用する。現状は保留理由が文字列であり、未保存原本にSourceDocumentIdがない。画面を閉じると結果一覧が消えるため、ブラウザー上の回答欄だけでは履歴・再開契約を満たさない。既存ReviewServiceはCanonical商品リンク用なので取込疑義と混在させない。

## 最小実装順

1. 隔離DBへ取込受付原本と疑義の永続化を追加。業務登録前でも受付IDとhashで原本参照を保証。原本は不変、既存SourceDocumentへの保存と受付段階を区別する。
2. 取込一覧の保留行に「確認する」を追加。疑義の理由、シート/行/列またはPDFページ、参照可能な原典、決定論的な判定結果と根拠を表示する。未特定の位置は「未特定」とし、ページ番号等を作らない。
3. 型付きの回答入力・確定。まず基準日指定と保留継続を対象にし、自由記述をコード/SQL/任意の変換命令として実行しない。確定者、回答日時、原本hash、疑義版、判断方式Human/Rule、根拠を追記保存する。
4. 対象原本・回答版を指定して再開。未解決の必須疑義がある間は保存しない。保存不明は再開不可とし、既存取込履歴照合を先に行う。二重クリック・再送・古い版に対する再開を検証する。
5. ENEOSの同価格数量競合・AOC省略対応を型付き判定へ接続。疑義の単位をファイル全体/商品行で区別し、商品の保留だけでファイル全体を成功と誤表示しない。

## 判断方式

Ruleは固定parser/検証による判定、Humanは本人の確定回答。LLMは将来の候補提示用adapterとして分離する。推定日と根拠は確定日と別項目。LLM候補だけで数量・価格・日付を確定しない。外部LLM呼出し、有料API、原本外部送信は今回未実施。導入時には送信範囲・モデル・入力hash・prompt版等を定義する。

## 検証する条件

- 保留原本を再起動後も参照でき、hashが不変。
- 出典セルと質問が対応し、文書内の命令文をシステム指示として扱わない。
- 回答確定後も過去の回答・根拠が残り、古い版更新は409等で拒否。
- 基準日指定の由来がHumanとして保存され、抽出日と区別できる。
- 未解決/保留継続は保存されず、解決した対象だけ明示再開できる。
- 再開を二度送っても業務登録とEvidenceが増殖しない。
- 保存応答不明でキューが停止し、回答操作で停止を迂回できない。
- 容量や価格の推測補完、数量加算、原本上書きをしない。

実装・単体・隔離DB・API・Edgeの順で検証し、確認用URLと操作手順を結果として報告する。既存55994以降の確認環境を止めない。本番配備、権限/ネットワーク変更は対象外。
